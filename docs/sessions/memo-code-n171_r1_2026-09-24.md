Written by Code 2026-09-24, answering `brief-code-n171-hash-fold_r1_2026-09-24.md` (including the 21:59 requirement in Step 3). Read on branch `Shane` at `0381872`, with the working tree dirty only in `docs/` before this work. Nothing is committed.

## In one paragraph

The fold now runs at arrival in the app, it abstains on the vacated tail, and a test shows that it changes no duration and no figure outside the per-vowel breakdown. **But step 1 found that the defect never reached a singer on the Sunless songs.** Every `#` in all six Sunless files, and in all ten Kabalevsky files, is in verse 2, Dann's engraved IPA line. Ilya reads verse 1 (Cyrillic) everywhere. So Text, Markup, and the per-vowel counts were already correct for these songs, and the fold changes nothing a singer sees for them. It protects a score whose *sung* verse carries a standalone `#`. On the way, the work found and fixed a bug in the fold itself.

## Step 1. Where the misalignment reached: nowhere live, for these files

**Every live consumer reads verse 1, and only verse 1:**

- Text (the poem from the score): `+page.svelte:396`, `scoreWordsText(collectScoreWords(ingestedScore.result.score, 1))`
- The seat's queue: `+page.svelte:387`, `readScoreText(ingestedScore.result.score, 1)`
- The clitic seat: `+page.svelte:506`, `findCliticFolds(ingestedScore.result.score, 1)`
- The vowel and IPA resolvers for Insights and Markup: `InsightsPane.svelte:114` and `VoiceProfilePane.svelte:588`, `buildUnderlayResolvers(readingScore, 1, …)`
- The Cyrillic line on Markup: `staff-renderer.ts:3188` draws `ev.syllable.text`, the primary (verse 1) text. Its own comment warns that `syl.verses` must never be drawn.

**Where the marks are, measured today.** `.musx` files through denigma and `MnxScoreParser`, the same path the frequency run takes:

| file | marks in verse 1 | marks in verse 2 |

| Sunless 01 | 0 | 2 |

The app's MusicXML fixture of Sunless 1 (`ingestion/fixtures/sunless-01-engraved.musicxml:435, :1643`) matches: two marks, both `<lyric number="2">`.

**So the file and line that decide it** are the `1` passed as the verse number at the call sites above. `score-metrics.ts:43-50` was wrong to say the misalignment "reaches `byVowel` and `byPitchByVowel`". For these files it reached nothing live. **INFERENCE:** the 18.46 percent to 8.15 percent measurement in `diction-marks.ts:42-51` was made against verse 2, since no other verse carries a mark. The harness that produced it is not in the tree.

**The Sunless 4 quotation in `diction-marks.ts:25-30` compares verse 1 against verse 2.** Cyrillic ⟨на⟩ is correctly on note 70. It is the IPA line that runs one note late.

**A second shape, not what the brief describes.** Through `.musx`, denigma does not hand the mark over as its own syllable. It arrives already joined to the syllable before it (`jɑ #`, with a space). In Sunless 4 the verse-2 syllable before it is missing from note 82, and verse 2 still runs one note late from note 83. `foldDictionMarks` only acts on a mark that stands alone (`o.text === mark`, `diction-marks.ts:181`), so on this path it folds nothing. MusicXML files, including the fixture, do carry the mark alone.

## Step 2. What changed

| `apps/web/src/lib/shane/vowel-resolver.ts` | `buildUnderlayResolvers` deletes the vowel and IPA for each vacated tail event of its verse, so they abstain instead of sustaining the last syllable. |

**Dann's rule is kept:** the mark is concatenated onto the syllable before it (`jɑ#`, `я#`), never discarded, and each break is recorded with the event it follows.

**DESK DEFAULT: `phonationBreak` is not switched on.** `phonationBreakEventIds` now has a source on every score (`score.dictionMarks.breaks`), but setting the flag would draw a new mark on Markup (`staff-renderer.ts:3180`). That is a visible change, so it is not in this brief's scope.
