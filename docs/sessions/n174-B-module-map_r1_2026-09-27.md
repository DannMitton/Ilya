## 2. Redraws from the spec's table, and why

   Alternative: `lib/notation-fonts.ts` at the app root beside `page-config.ts`; equally
   legal, one more top-level file.

   `+page.svelte:125` owns the state. In `markup/` the test edge points upward. Low stakes;

   Whether `ShaneEngineError` is also renamed is step A's territory.

## 8. The ratchet rule, in prose

`scripts/ratchets.mjs` today (94 lines) walks `apps/web/src` and each `packages/*/src` for
`.ts` and `.svelte` (`:28-29`), skips tests (`:30`, `:54`, `:72`), and for every import specifier
(`:70`, a regex over `import ... from` and `import(...)`) applies two rules: a package
must not import `$lib`, `$app`, or `apps/` (`:76-79`), and app code must not reach a
package by relative path (`:80-82`). Breaches are collected and the script exits 1 (`:90-93`).

The new rule is a fourth check inside that same loop, "4. MODULES", shaped like this:

- A table of the six module names and, for each, the set it may import:
  `reader: {}`, `score: {reader}`, `voice: {reader, score}`, `analysis: {reader, score, voice}`,
  `markup: {reader, score, voice, analysis}`, `insights: {reader, score, voice, analysis}`.
  (Or the spec's looser version, which only lists what the three base modules may NOT
  import; the table above is the graph as it will stand, and a ratchet may as well hold it.)
- For a file under `apps/web/src/lib/<m>/` where `<m>` is in the table, resolve each
  specifier to a module: `$lib/<n>/...` gives `<n>`; a relative specifier gives the module
  of the resolved path (walk `../` against the file's own folder). Anything that resolves
  outside the six is ignored by this rule.
- If `<n>` is one of the six, `<n> !== <m>`, and `<n>` is not in `<m>`'s allowed set,
  push `MODULE <file> imports "<spec>". <m>/ may not import <n>/.`
- One more line so the rule keeps meaning: any file under `apps/web/src/lib/shane/` after
  slice 6 is itself a breach (`MODULE <file> is under lib/shane/, which no longer exists`).
  Until then that line is commented out or gated on the folder being empty.

Two shortfalls in the script that the rule inherits, and what each costs:
- Tests are exempt (`:72`). The two tier-1 and tier-2 test edges above would pass the
  ratchet as written. Dropping the exemption for rule 4 only (keep it for rules 2 and 3,
  whose fixture argument at `:17` is sound) costs one condition; then the tests must
  obey the same table, which the map in section 1 already arranges.
- The regex at `:70` does not see `new Worker(new URL('./x.worker.ts', import.meta.url))`.
  Both Workers stay inside `reader/` beside their facades, so nothing is missed today;
  a second pattern for `new URL('...', import.meta.url)` is the guard for tomorrow.
