## Amendments

1. **Part 1, the loop has a guard, and it is structural.** State: no page signals anything back into the slice except the title header's measured height (`TitlePage.svelte:144-146`), which does not depend on the lines. The footer reserve comes from one measurement that does not depend on the slice: a hidden `PageFooter` rendered with the legend of the whole document's lines (`buildProvenanceLegend(lines, ...)` over all lines, `provenance.ts:174`) and `showsRichterIpa(lines)` over all lines, measured by its own `onheightchange` (`PageFooter.svelte:63-67`), and reserved on every page (DESK DEFAULT, reversible: a page without the legend reserves at most one legend row of slack, about 10 px, inside the 15 percent rule). Each page still draws its own legend. Keep `FOOTER_MAX_HEIGHT` as the floor, `Math.max(FOOTER_MAX_HEIGHT, measured)`, the N.83 precedent (`MarkupPane.svelte:478-498`), so a short footer reserves what it reserved and no existing document repaginates. Alternative if Dann wants the exact per-page reserve: a ratchet, the reserve on a page only grows within one document's layout and resets when `lines` change; it converges but can leave the same slack. Reason: case 5 above oscillates with no guard. Evidence: `Paper.svelte:47`, `:59-61`, `:76`; `TitlePage.svelte:140-142`; `provenance.ts:181-198`.
2. **Part 1, measure wrap counts and cut points, not pixel heights.** The one measurement is a measuring column at the page's content width (816 − 88 − 96 − 4 = 628, `TitlePage.svelte:209-215`; first visual row 628, later rows 600 under the 28 px hanging indent, `VerseLine.svelte:92`), with `--row-gap: 0`, that renders every line once and reads, per line, the number of visual rows and the index of the first word on each (from each `.word-stack`'s `offsetTop`), plus two constants read from any one-row line: its drawn box height (the 56.3) and its lowest child box below the row box (the 1.1). The pure slicer then computes a line's height on a page as `rows × rowBox + (rows − 1) × pageGap`, and the page's fit as `Σ heights + (lines − 1) × pageGap + overhang ≤ window`. Cuts fall at measured wrap points, keeping two rows each side (`page-config.ts:181`, `:188`). `rowsOf`'s seven-word estimate (`page-config.ts:109-119`) goes, with its comment. Reason: case 6; a pixel height measured in place changes when the line changes page. Evidence: `VerseLine.svelte:87-93`; `TitlePage.svelte:169`; `SubsequentPage.svelte:86`.
3. **Part 1, later pages take the same rule.** `SubsequentPage` computes rows and gap the way `TitlePage` does (try 10, floor 18, cap 28, gap floored), from its own measured header (`SubsequentPage.svelte:61-65`) and the measured footer reserve; the constant `subsequentRowGap` (`:73`) and `LINES_PER_PAGE` as a budget (`page-config.ts:97`, `:166`) go.
