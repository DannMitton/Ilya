## 1. What `?reader=ilya` is

**The route.** `useIlyaReader(search)` is true where the address query has `reader=ilya` (`apps/web/src/lib/omr/scan.ts:25-27`). `ScoreUploader.svelte` consults it twice: on a drop with staves found, it calls `handleFile(file)` instead of `readScanAsScore` (`:286-287`); on restore of a stored scan it takes the old reader instead of `restoreStoredScan` (`:790-805`). Nothing else in `apps/web/src` reads the flag (grep of `reader=ilya` this session: `omr/restore.ts`, `omr/scan.ts`, `omr/scan.test.ts`, `score/ScoreUploader.svelte`, `score/ingestion/ingest.ts`, all comments or the two call sites).

**From a page image to a score, in order.**

1. The page is rasterized by the same functions homr's route uses: `rasterizePdf` at 400 dpi for a PDF, `toGreyscalePng` for a picture (`ScoreUploader.svelte:643-647`; the homr route, `omr/scan.ts:38-41`).
2. Before the read, the first page is probed for its printed clef and key signature so the clef-and-key prompt can pre-fill (N.97): `probeFile` (`ScoreUploader.svelte:709-725`) calls `WorkerPageReader.probe` (`reader/page-reader.ts:115-136`), which runs `reader.probe_clef_key` in Python (`page-reader.worker.ts:144-157`; `tools/e16-harness/reader/reader.py:1501`). The singer then answers clef, octave, and key in the `asking` state (`ScoreUploader.svelte:546`, `:940-1000`), with `prefillFrom` (`score/ingestion/clef-key-prompt.ts:19`).
3. `readAsked` (`:736-752`) calls `handleFile(file, answers, fallback)`, which dispatches through `ingestScoreFile` with the `readPages` seam (`:575-585`; `score/ingestion/ingest.ts:232-247`).
4. `readPages` posts every page's greyscale PNG and the answers to the worker (`ScoreUploader.svelte:677-682`; `page-reader.ts:93-115`).
5. The worker runs the Python driver `read_pages`: for each page `cv2.imread`, then `envelope.run(cfg, ctx_in)`, which chains measure numbering across pages, isolates a page that raises, and aggregates a `ReadReport` (`page-reader.worker.ts:159-259`).
6. The result `ro` (clef, key, verses with notes, measures; `reader/recognized.ts:64-70`) is turned into MusicXML by `recognizedToMusicXml` (`ingest.ts:243`; `score/ingestion/recognized-to-musicxml.ts`), with `<clef-octave-change>` from the singer's answer (`:269-270`), and parsed as a MusicXML file with provenance `via: 'reader'` (`ingest.ts:244-248`).
