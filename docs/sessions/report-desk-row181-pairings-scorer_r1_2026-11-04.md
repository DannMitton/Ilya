## The scorer

`/root/c181/scorer/score_pairings.py SONG PAIRINGS.json MUSICXML [OUT.musicxml]` (with `/root/c181/scorer/cursor_ids.py`).
- Input: a PairingMap (`pairings.ts:122-134`), or an object with `pairings`, or the `idbdump.json` that `measure_c181.mjs` writes (the record with the most pairings).
- Mapping: by id (recomputed cursor id); a pairing whose id is not in the file takes the unclaimed sung note in the same bar whose onset is nearest (pairings have no pitch, so `map_notes`'s pitch rule cannot be used); a pairing whose bar does not exist is dropped. The three counts print. Shared ids: DESK DEFAULT, the note that carries a lyric in the file, else the first.
- Output file: copy of the page MusicXML with every `<lyric>` removed and one `<lyric number="1">` written per syllable pairing (text = the pairing's `cyrillic`; syllabic from `origin` line and word: begin/middle/end, or single). Then `score114.score(n, file)` runs, so (b), (a), (c) are score114's own. Not covered: grace notes never become events (`musicxml-parser.ts:703`), so a lyric on a grace note cannot be carried by a pairing (song 1 has 4 grace notes).
