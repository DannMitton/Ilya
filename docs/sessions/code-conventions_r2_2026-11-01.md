## 1. Names in code follow the names on screen

A concept's code name is its English screen name, in the case its kind requires. After consistency batch 3, MELODY is `melody/` (folder), `MelodyPane.svelte` (component), `tab.melody` (i18n key). **Reason:** a newcomer goes from the screen to the code without a lookup. `apps/web/src/lib/names.ts` (consistency batch 1) records each concept's screen name, code name, and retired names.

**Known exceptions today, closed by batch 3:** the folder `apps/web/src/lib/markup/` (15 files) and `MarkupPane.svelte`; `tab.markedScore` (the score tab); `BAND_IDS.scoreMarkup` (the VOICE band, `sections.svelte.ts`); `console.placeholder` (the ANALYSIS station's heading); `cosmetic.heading` (NOTATION); `songs.heading` (REPERTOIRE). The rule is met when this list is empty.

## 2. Case by kind of name (Google TypeScript Style Guide, "Identifiers")

| kind | style | example in the tree |
|---|---|---|
| class, interface, type, enum, Svelte component | UpperCamelCase | `InputViews`, `TextWitnessPair` |
| variable, parameter, function, method, property, `$state` variable | lowerCamelCase | `chooseWitness`, `shownWitness`, `selectedCellIndex` |
| module-level value meant never to change, including `as const` id maps | CONSTANT_CASE | `CYRILLIC_VOWEL`, `BAND_IDS` |

**Why capitals stay out of other names (Dann 12:28).** The guide reserves CONSTANT_CASE for "global constant values, including enum values", and says a value that "can be instantiated more than once ... must use `lowerCamelCase`". Capitals in a name tell every reader "this does not change"; a component or folder in capitals would tell them something false. About 500 module-level constants in `apps/web/src` follow it (`git grep -nE '^(export )?const [A-Z][A-Z0-9_]+\b' -- apps/web/src | grep -v test`: 512).

**Acronyms are words:** `ipaOf`, `estimateIpaWidthPx`; the guide's own example, `loadHttpUrl`, not `loadHTTPURL`. A name a platform fixes keeps its form.

**Element references** end in `El`: `drawerContentEl` (22 in the tree).

## 3. File names

- **A module:** kebab-case, `witness-lines.ts`. **Reason:** the tree's own practice: of 235 non-test modules in `apps/web/src`, 191 are kebab-case, 99 one word, 3 camelCase (`bandState.ts`, `profileStore.ts`, `voiceTypes.ts`, renamed in batch 3), none snake_case. The Google guide's snake_case file names (one sentence under "Imports") are declined because the tree has none.
- **A module that uses runes** is `name.svelte.ts` (17 files). A pure rule a test must reach lives in plain `.ts`, because vitest runs in Node without Svelte's runes (`bandState.ts` says why).
- **A Svelte component:** UpperCamelCase, `TextWitnessPair.svelte` (65 in `apps/web/src/lib`).
- **SvelteKit route files** keep the names the framework requires (`+page.svelte`).
- **A test** sits beside its module: `witness-lines.test.ts` (249 files). Browser tests live in `apps/web/e2e/` and `apps/web/e2e-phone/` (Playwright), outside the eight gates.

## 4. Storage keys and i18n keys

**Storage.**
- localStorage keys: `ilya:` then lowerCamelCase, `ilya:openStations`.
- IndexedDB databases and Cache names: `ilya-` then kebab-case, `ilya-library`, `ilya-static-v1`, because browser tooling shows those names where a colon reads badly.
- A version lives inside the stored value (`{ v: 3 }`), not in the key, unless an old and a new shape must live side by side.
- `shane.profiles.v2` breaks both rules; batch 3 renames it. Before release, Dann ruled a rename needs no carry-over read (12:00, 12:25: nobody but him holds data). After release, `ARCHITECTURE.md` invariant 10 governs: "A stored id changes only with a migration", and every rename ships a migration that reads both.

**i18n keys.** Dotted segments, each lowerCamelCase; two to four segments, the last naming the concept, not the wording (`tab.melody`, never `tab.markedScore`). The 30 kebab-case `legend.*` keys stay until batch 3. New placeholders are `{name}`; `%s` (55 values) is legacy. The prefix index at the head of `i18n.ts` (it says "881 keys"; the file holds 1,018) will be regenerated by a script batch 3 adds.

## 5. Comments (Dann 12:05 to 12:07)

- **Every source file opens with a comment** saying what it is for and what it must agree with. Today 226 of 233 non-test modules in `apps/web/src/lib` do; a test that checks the comment exists (never its wording) comes with batch 2.
- **A comment answers one of three things:** purpose (why this exists), function (what it does where the code does not say so plainly), or consequences (what else changes or breaks if this changes). One that answers none is not written.
- **Relationships an import search can find** (who imports whom) live in the module map in `ARCHITECTURE.md`, generated by a script and checked by `pnpm ratchets` (batch 2). A comment names only what that search cannot show: two sites that must agree, an event a distant part listens for, a value another package depends on.
- **Cite a name, never a line number.** Line numbers go stale on the next edit; 106 comments cite one today, swept in batch 2.
- **Places in comments are written as a singer sees them:** "draws the MELODY page".
- **Rulings:** this tree's headers lead with a short thesis in capitals and cite a ruling by number, date, and words ("WHAT A CLOSED BAND SAYS, AND NOTHING ELSE. N.115 ... RULED BY DANN 2026-09-10", `bandState.ts`). An `N.` number is a numbered design item recorded in `docs/memory/` and `docs/sessions/` (`ARCHITECTURE.md`, "Where decisions are recorded"). A number alone tells a newcomer nothing, so give the date and the words.

## 6. One home for one fact

Logic needed in two places lives in one named, documented module both import (the punctuation sets and the Cyrillic vowel lists are the known cases, batch 5). Prefer a plain function called from several places over a copy, and a plain name over a clever one: the code stays approachable to people reading it to understand and improve it (Dann 11:52). Do not `export` a symbol nothing outside its file uses (the audit found 339).

## 7. What enforces this today

No linter or formatter is configured: no ESLint or Prettier file is tracked, and no `lint` or `format` script exists. Indentation is tabs. The mechanical guards are `pnpm check` (svelte-check), the vitest suites, and `scripts/ratchets.mjs` (file size ceilings, layering, package surface). Do not add a formatter without asking; it would rewrite every file.
