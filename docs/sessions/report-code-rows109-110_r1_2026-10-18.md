## 1. Row 109: Text shows the witness there is, and each witness keeps its marks

**A, the fallback.** `lyricsHas` is Lyrics' text or a score's derived words (`+page.svelte:450`); `shown` is `shownWitness(...)` (`:453`, `apps/web/src/lib/text/witness-lines.ts`): Lyrics where it holds text, otherwise Poem. The switch point is `textLines` and only it (`:466`, review r2 amendment 2): `textLines` alone feeds `effectiveLines`, `Paper`, and `ReadingAid`, and raw `lines` stays Lyrics' for `poemQueue`, the seats, `drawnUnderlay`, Markup, and Insights, none of which I touched. The poem is transcribed beside Lyrics by `witnessLines` (a try/catch around `processText`, so `poemLines` is one expression, `:457`), only while Text shows it and the dictionary has loaded. `emptyTextNotice` reads the shown witness's text (`shownText`), so a poem-only song draws no "enter" notice.

**D, the marks.** `WordMarks` (`apps/web/src/lib/text/word-marks.svelte.ts`, 85 lines) holds the four maps (stress, ё, syllables, spot) with the page's own handler bodies as methods (`assignStress`, `revertStress`, `toggleYo`, `setSyllable`, `toggleSpot`, `carry`, `clear`). The page owns two instances, `lyricsMarks` and `poemMarks` (`:428`); `marks` is the shown witness's (`:454`). Every Text tool works on `marks`: the inspector's props and handlers, the Paper and `ReadingAid` display maps, `effectiveLines`, and `handleReset`. A mark that changes the sound re-runs the shown text: Lyrics through `runPipeline`, the poem through its derived lines, and `selectedWord` is read from them afresh (`rerunShown`, `:2266`). `selectedWord` clears when the shown witness changes. `claimDerivedPoem()` stays in the four handlers; with the poem shown Lyrics is empty and there are no derived words, so it returns without writing (read, and covered by the browser test below).

- **Parity (amendment 5, desk decision 8):** the poem's stress, ё, syllable, and spot marks are session state; only its glosses are on the song. `SongRecord.publishedGlosses?: GlossRow[]` (`types.ts`), `SongFields.publishedGlosses` and `publishedGlossAnchors` (`library.ts`), `doc.publishedGlosses` and `doc.publishedGlossAnchors` (`document.svelte.ts`): additive, stored only while not empty, the `publishedPoem` pattern, validated by `validateRecord` with the glosses' own row filter, carried in a binder, no schema bump.
- **A poem edit carries its marks (amendment 6):** `carryPoemEdit` diffs the poem as it was against the poem now (`diffWordGrid`, `text-diff.ts`) and re-keys the marks and glosses, dropping a gloss whose anchor word no longer stands there. Test l is `witness-lines.test.ts`, "a mark and a gloss on a poem word follow it when a line is inserted above".
- **Never written into Lyrics' maps:** two instances, no shared key.

**B, Lyrics is fed first by the score.** Unchanged for a score with words (`+page.svelte:2873` follows it). For a wordless score (every scan today), `lyricsTakesPoem(wordlessScore, lyrics, poem, placements)` (`witness-lines.ts`) is true for an empty Lyrics, a poem, and no placements; it runs in two places: a poem edit that arrives whole (`how === 'paste'`, which a dropped page and a paste both are, `handlePoemEdit`, `:2431`), with a score attached that carries no words (`noLyricsFile !== null && ingestedScore !== null`, review r1 amendment 5), and an upload of a wordless score onto an empty Lyrics with a poem (`:2873`, inside the existing `origin === 'upload'` test, so a restore never refills). The copy goes through `handleInput(text, 'paste')`, and N.145's first-transcription seat then runs `firstPass`. A poem typed key by key is not copied, by decision 7.
