## 2. Part 1. Ilya seats automatically

`applyArrival` calls `seatCliticFolds(ingested.result.score, doc.pairings)` at
`+page.svelte:2339`, immediately after `mergeOnUpload` writes the merged map.
There is no proposal, no button, and nothing to press. A lone vowelless clitic
cannot exist on the page.

**AFTER THE MERGE, so it can never overwrite the singer.** `mergeOnUpload`
returns an existing map untouched on a re-upload; `isCliticSeated` then finds
every fold already seated and `seatCliticFolds` returns that map unchanged. It
is idempotent, and a test pins that.

**IT IS NOT GATED ON HOW THE SCORE ARRIVED.** A song saved before this ships
carries a map with no seat in it, so the seat has to run on a restore too. On a
song that already carries it, the run is a no-op.

**The limit stands, and it is where the code refuses.** `findCliticFolds` acts
on one divergence class. Where the file and the transcription diverge for any
other reason, `align` either loses sync and returns null, or `foldAt` refuses on
one of its five conditions, and nothing is seated. Your words, 2026-09-04: *"I
like your distinction, especially when we expand Ilya to process Italian text
where multiple syllables on a single duration are common."* One-vowel-per-note
is not built.

## 3. Part 2. A blanked note draws nothing

The run's leftover note stays UNDECIDED. Nothing is written into the map for
it, because Ilya may claim neither an `empty` note nor a melisma.

**What changed is the render, not the decision.** `CliticFold.blanked` names the
notes the queue could not reach; `+page.svelte:413` turns the seated folds'
`blanked` lists into a `Set`, minus any note the singer has since decided;
`pairedCyrillic(map, blank)` maps those ids to the **empty string**. The
renderer reads `options.cyrPreview?.[ev.id] ?? ev.syllable?.text ?? ''`
(`staff-renderer.ts:709`), and `??` keeps an empty string rather than falling
through it, so `if (cyr || ipa)` at `:2469` then draws nothing at all. The IPA
line and the withheld siglum are suppressed on the same ids
(`VoiceProfilePane.svelte:754`, `:774`), or the note would carry a
transcription over an empty cell.

**The positive control is in the test**, because a negative result without one
proves nothing: `clitic-seat.test.ts` first asserts that WITHOUT the blank set
the close still reads `о ди но ка ка`, the defect you walked, and then that with
it the last note maps to `''`.

## 6. Part 4. The punctuation

`carryPunctuation` (`clitic-seat.ts:322-356`) puts the file's own trailing mark
back on the re-seated cell.

**It is cheap, and this is why.** Inside a run the file is exactly one cell
ahead of the queue: that is the invariant the run is DEFINED by, not an
assumption about it. So the text now going onto cell `c` is the text the file
printed on cell `c + 1`, and its punctuation comes from there.

**The guard is the whole rule**, and it is your wording: the mark travels only
where the two texts are the same word once punctuation is off both. Where the
engraver's division and Ilya's differ (`про`/`гляд` against `прог`/`ляд`)
nothing is carried.

**Measured on the fixture: fourteen marks in, fourteen marks out, in the same
order.** `я,` of заветная moves back one note and keeps its comma, where before
this it read a bare `я`.
