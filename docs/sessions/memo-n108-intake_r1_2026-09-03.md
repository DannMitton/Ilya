## 6. NOT ESTABLISHED

**"NOT ESTABLISHED beats a complete invented answer."**

1. **What "which it is" means for a PDF was not written down anywhere.** The
   brief says "A PDF asks once, in place, which it is. Do not guess", and no
   ruling, design return or prototype elaborates it. This build reads the two
   answers as the two kinds the one intake holds, **the poem or the score**,
   because every other format the sniff meets settles itself (text typed or
   pasted is the poem; MusicXML, MNX, the three ZIP containers and a photograph
   are the score, the last by the brief's own "a photograph goes to the
   reader"), and a PDF is honestly either. The poem answer needed a capability
   that did not exist, so `extractPdfText` was written for it. **If Dann meant
   a different question, the question and its two buttons are one component
   state and one i18n block, and the extraction is one exported function.**

2. **Design's prototype hides the field once material arrives (`:200`) and this
   build does not.** In a static mock the state comes from a selector; in the
   app a poem arrives one keystroke at a time, and a field that unmounts on the
   first character cannot be typed into. The field stays and Replace on the
   poem selects what is there, so the next paste takes its place. **Dann's to
   rule on the walk.**

3. **The prototype also hides the two buttons once material arrives** and
   leaves Replace to do the picking. They stay drawn here: a phone cannot drop
   a file, so hiding them would strand a singer who has a poem and wants to add
   a score. **Dann's to rule.**

4. **The intake's fill and rule are Design's placeholder.** `--paper-light` and
   a 1px dashed neutral at ink 0.28, from the prototype at `:190`, which marks
   the fill PLACEHOLDER. No hex was invented. What is genuinely spent is "hue
   names place": sage named the text intake and lavender the score intake, and
   there is one place now. **Dann's to rule.**

5. **The score receipt's line is the file name.** The prototype draws "3 pages
   · score markup", and Ilya has no page count for a MusicXML. The file name is
   what the tree actually holds and what a singer would recognise. Whether it
   should carry the format label (`upload.format.*`, which is ratified in both
   languages) instead or as well is **not established**.

6. **The word count is the transcription's, so it appears only after
   Transcribe.** The receipt says `4 lines` from the first keystroke and gains
   `15 words` when the pipeline has run. That follows the prototype's own note
   that this is "the instrument line's count". Whether a singer wants a count
   of the words they pasted, before transcribing, is **not established**.

7. **"Continue to analysis" survives.** A dropped score still ends on the
   engine's confirm panel before the receipt appears. The brief did not ask for
   it to go and the prototype does not draw the engine's states at all, so it
   was kept. Whether the receipt should appear the moment a file parses is
   **not established**.

8. **A dropped file that is not a format the ingest reads still earns the
   ingest's refusal.** A `.txt` of a poem dropped on the field returns
   `upload.err.unrecognised`, exactly as it does today. Whether the one intake
   should read a plain text file as the poem is **not established** and was not
   built; the brief's list is "any format `ScoreUploader.svelte` reads today".

9. **The OCR camera icon stays on the field, and the two picture routes stay
   apart.** The icon reads Cyrillic TEXT out of a picture; the photograph button
   reads a SCORE out of one; a dropped picture goes to the score reader, by the
   brief's ruling. The button a singer presses is what says which they meant.
   The brief does not mention OCR, so nothing was removed. Its own hidden input
   keeps `accept="image/*"` on a phone, untouched, because iOS registers image
   types and it was never what N.70 was about.

10. **The score's Replace and the two picker buttons were not clicked with a
    real pointer during the walk**, because an OS file dialog would have hung
    the automated pane. Their `accept` attributes were read out of the live DOM
    instead, which is what the N.70 gate asks for, and the route they feed was
    proved by drop, which is the same `onfile` → `take` → sniff path.

11. **The walk ran against a trimmed dictionary.** The browser pane runs hidden,
    which throttles `setTimeout` to seconds per call, and the loader yields
    once per 1,500 entries across roughly 943,000 of them, so a real boot never
    finished inside this session. A 413-entry shard holding the walk poem's own
    words was served from the gitignored build directory for the walk and
    **removed afterwards**; both `data/` directories are back to the shipped
    manifest. Nothing about the intake depends on the dictionary's size. This
    is a measurement artefact of the pane, not a finding about Ilya.

12. **Nothing entered `static/`**, so there is no byte count to report.
