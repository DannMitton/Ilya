A3. Sequence, in order (ritual phases, CR:43 `'idle' | 'sing' | 'pause' | 'listening' | 'sweep' | 'landing'`)
1. Tap on a vowel button (VC:339 `onclick={() => tapVowel(v)}`) -> `tapVowel` (VC:231-239). If `ritual.phase !== 'idle'`: a tap on the take's vowel calls `ritual.cancel()`, any other vowel is ignored, return (VC:232-236). If idle: `selected = v; startTake(v)` (VC:237-238).
2. `startTake` (VC:223-230): records `takeVisible` ('hidden' | 'zone') from the hide toggle; closes the readings list if hidden mode; `notice = null; confirmingClear = false; tookAny = true; ritual.begin(v)`.
3. `begin(v)` (CR:156-177): refuses unless idle (returns false, CR:157). Takes id `++takeId`; phase 'sing'; `runCountIn(onStep, after)` (count-in.ts:334-339): the step at 0 fires synchronously, the rest through `after` (timers kept in the ritual's `timers` array, CR:104, 113-115).
   - 0 ms 'sing': cue `pacifier.singFirst`; `tick()` (CR:173-174).
   - 1000 ms 'two': cue `calib.readiness.countTwo`; tick.
   - 2000 ms 'one': cue `calib.readiness.countOne`; tick.
   - 3000 ms 'pause': phase 'pause'; cue `pacifier.pause`; no tick (CR:168-172).
   - 6000 ms 'fry': `startListening(id, v)` (CR:167, 179-197).
4. `startListening`: phase 'listening'; cue `pacifier.beginPhonating`; `sessionStarted = true`; `deps.session.start(v, deps.voiceType(), {onStableFry, onComplete, onError})`. The microphone is requested here, 6 s after the tap, and not before (count-in.test.ts:58-68 pins "no capture session starts before the fry step").
5. Engine: waits for a stable fry (gate every 250 ms over a 1.0 s window, live.ts:381-419; up to 10 s). On accept: `recording = true`, trims to a 0.5 s pre-roll, calls `handlers.onStableFry()`, then `setTimeout(finish, SWEEP_S*1000)` (live.ts:543-560).
6. `onStableFry` -> `startSweep(id)` (CR:184-186, 199-219): only if phase is 'listening'; phase 'sweep'; cue `pacifier.nowSustain`; `sweepStartedAt = Date.now()`; progress interval every 50 ms (250 ms under reduced motion) computing `min(1, elapsed/3000)`; `after(SWEEP_MS)` sets `clockDone = true`, `progress = 1`, clears the interval, calls `maybeDeliver`. The bar is a fixed 3.0 s clock "independent of the engine's delivery time" (CR:210).
7. Engine `finish` (after 3.0 s; trims, runs `runCapture` on the main thread, ~100-300 ms per live.ts header) calls `onComplete(formant)` or `onError`. Ritual `onComplete` (CR:187-191) stores `pending = formant`, calls `maybeDeliver`. Ignored if phase is idle or landing.
8. `maybeDeliver` (CR:221-239): needs `clockDone && pending`. Sets `sessionStarted = false`, phase 'landing', progress 1. Re-take rule (CR:228-236): `deps.previous(v)` is the wizard's guarded stored reading; a Provisional new reading over a Captured stored one gives cue `pacifier.rolledBack` and `onRolledBack`; otherwise cue `capture.uncertain` (Provisional) or `pacifier.captured` and `onCaptured`. Then `toIdle()` at once under reduced motion, else after 900 ms (CR:237-238).
9. VC's callbacks (VC:98-114): `onCaptured` records the take (`readingTake`), calls the wizard's `onCaptured(v, {...f, visibility: takeVisible})` (the wizard's `commitReading` guards, persists, returns the profile entry, CW:719-748), `keepNotice()`, then `advanceFrom(v)`. `keepNotice` keeps the cue as a notice unless its key is `pacifier.captured` (VC:118-120; `staysAfterTake`, voice/chart/screen-logic.ts:105). `advanceFrom` (VC:123-129): next vowel by `nextVowel(sung+v, v, pass)` goes to `pendingSelected`, which becomes `selected` only when phase is idle (effect VC:187-192). With `pass` set and no next vowel and no notice, `returnWhenIdle = true`, and a second effect calls `onReturn()` at idle (VC:193-198). All ten sung with no pass: rests where it is (VC:128 comment).

A4. Cancel, Escape, second tap, Stop
- `cancel()` (CR:248-258): false in 'idle' and 'landing'. Otherwise `takeId++` (so late callbacks from the session are dropped), `toIdle()` (clears every timer), `session.cancel()` only if the session had started, cue `pacifier.cancelled`, `onFailed(v, {code:'CANCELLED'})`. The session's own CANCELLED confirmation is dropped by id (CR:188-194, test capture-ritual.test.ts:285).
- Callers of cancel: second tap on the take's vowel (VC:234); Stop button while `active` (VC:246-248); Escape (VC:259-264, `<svelte:window onkeydown>` at VC:269, only when `ritual.cancellable`, calls `preventDefault`); the session itself via CANCELLED/error (CR:241-246 `fail`); unmount (`ritual.destroy()`, VC:179-183, fires no event, CR:260-273).
- Landing cannot be cancelled: after the reading is delivered `cancel()` returns false (CR:249). A tap on the same vowel in landing calls `cancel()`, which returns false; a tap on another vowel is dropped (VC:232-236). `stopDisabled` is true in landing (VC:266). Header comment: "a second tap on the vowel, Stop, and Escape ... all call `cancel()`" (CR:17-19).
- `active` = phase not idle and not landing (VC:201); `running` = phase not idle (VC:202).
- Stop button doubles as Start over: when not active and not running, first tap sets `confirmingClear`, second calls `onClearAll` (VC:251-257); disabled when nothing sung (VC:266).
- `tapAction()` in count-in.ts:347-358 (begin/cancel/ignore by wheel state) has no production caller. Only voice/count-in.test.ts imports it. The ritual and VC do not use it.

A5. `pass` and `startVowel`
- `startVowel: Vowel` (VC:59): the vowel the screen opens on; `selected = untrack(() => startVowel)` (VC:74). Read once at mount; VC is remounted on each wizard phase entry (CW:1122-1139).
- `pass?: Vowel[]` (VC:60-61): "a list to walk, then return to the summary (a re-take from the summary). Absent: Ilya's order." Used only in `advanceFrom` (VC:125-127) via `nextVowel(..., pass)` (voice/chart/tour.ts:22-26: the vowel after `last` in the list, first if `last` is not in it, else null).
- Wizard builds both from `opening` (CW:1138; voice/chart/opening.ts:18-24): `openTour` (start = first vowel Ilya's order lacks), `openChallenging` (first unsung of ɨ ɪ ʌ), `openRetake(vowels)` (start = vowels[0], pass = vowels).

A6. Other facts in the take
- The tick: lazily constructs one `AudioContext` on the first sung beat (a user gesture), plays a 660 Hz sine of about 0.1 s; failures swallowed; context kept across takes and closed in `destroy()` (CR:126-144, 267-272).
- `takeVisible` is fixed at the tap; the hide checkbox is disabled while running (VC:393).
- Every take (success, rollback, failure, cancel) is recorded through `onTake` -> `recordTake` (CW:700-704; voice/takes.ts, 50 per vowel).
- Take id: each take has an id; callbacks from earlier takes are dropped (CR:103, 158, 166, 185, 188, 193).
