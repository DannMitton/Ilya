## 2. The integer conversion (what to check, item 2)

Established by row 81: a float `tessdata_best` model does not initialise on the core tesseract.js 7.0.0 picks under Node, and the browser picks by the same `getCore` (report lines 53 to 61). Established by row 81: Ilya's shipped `rus` is `4.0.0_best_int`, 5,053,706 bytes unzipped against 15,301,764 for the float `rus` (lines 48 to 50).

Fable's knowledge, not verified this review: `lstmtraining` writes a float model; `lstmtraining --stop_training --convert_to_int --continue_from <checkpoint> --traineddata <starter traineddata> --model_output <file>` writes the integer form, which is what `tessdata_best_int`-style files are. Whether a model converted this way reads the same text as its float parent is an empirical question and row 81 left it NOT ESTABLISHED. If the integer form does not load on the default core, or reads differently, the training has produced nothing Ilya can ship, and the row must know that before Dann is asked about bytes.

Projection, marked as mine: by row 81's own ratio for `rus` (15,301,764 float to 5,053,706 integer), the integer `Cyrillic` would be near 12 MB, over twice the shipped `rus`. That is an inference from one ratio, not a measure; the row measures it.
