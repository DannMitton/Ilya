## 1. The keyboard

`ProfileSwitcher.svelte`'s `selectAll` action called `node.focus()` and
`node.select()` unconditionally. Focus now depends on modality:

```
const pointerIsFine =
    typeof matchMedia === 'function' && matchMedia('(pointer: fine)').matches;
```

**How the pointer is detected, and what a device reporting both does.**
`(pointer: fine)` answers for the PRIMARY pointer, which is the query the
drawer's pull already uses for its own geometry. A device with both answers for
the one it is being driven with: a touchscreen laptop and an iPad with a
trackpad attached report `fine`, keep the desktop's behaviour, and cost nothing,
because a device with a pointer has a hardware keyboard and nothing pops up. A
phone reports `coarse` and is left alone. `(any-pointer: fine)` would have been
wrong: it answers "is such a pointer present anywhere", not "is this how the
singer is working".

If `matchMedia` is absent the code does not focus. An unasked keyboard is the
worse of the two failures, though no browser reaches that line without the API.

**The selection is not gated.** It moved to a `focus` listener that fires once
per mount, so the phone still gets what the prefill is for: tap the field, the
keyboard comes because you asked for it, and `Voice 1` is already selected so
typing replaces it. Once only, so a later tap to fix a typo places a caret
instead of fighting you for the word.

The fine-pointer path calls `focus()` and then the same selection directly,
without waiting for the event, so the desktop depends on nothing but the two
statements this function has always run, in the order it always ran them.

No `autofocus` anywhere. The prefilled name is untouched.

## 2. The courtesy prompt

`.profile-empty` takes the transcription's treatment. The declaration I copied
is **`.empty-directive` in `Paper/TitlePage.svelte`**, every type value of it:
serif, italic, 1 rem, 1.6 leading, `--ink-tertiary`, centred, capped at 480 px
and centred by auto margins. Nothing was invented.

What I did not copy is that rule's `display: flex` with `flex: 1`, which is how
the transcription centres its line vertically inside `.page-content`. This
parent, `.profile-content`, already carries `justify-content: center`, so the
vertical is done; `align-self: center` overrides the parent's
`align-items: flex-start` for this one element. That parent's left
justification belongs to the calibration plea, and **`.profile-line` is not
touched**: it keeps its own rule, its left justification, and one sentence per
line, per your ruling of 2026-07-13.
