## 3. The design (DESK DEFAULTS, each reversible)

1. **The fix lives in `page-image.ts`, not in the uploader.** `toGreyscalePng` tries `createImageBitmap` first, as today (Safari can decode HEIC itself; that path is kept and not measured here). On failure, and only when the bytes sniff as HEIF (`isHeifImage`), it calls a new module `apps/web/src/lib/reader/heic-decode.ts`, which lazy-loads a WebAssembly HEIF decoder, decodes the primary image to RGBA, and returns it; `toGreyscalePng` draws that to its `OffscreenCanvas` and continues unchanged. Every score route benefits with no edit. The poem route takes the ink it already has: `page-image.ts` exports `inkFile(source: File, ink: ArrayBuffer): File`, which returns a File of the ink named `<stem>.png` with type `image/png`, `stem` from `source.name` as `pieceIdFor` derives it (`:34`); `ScoreUploader.svelte` calls `readAsPoemByOcr(inkFile(file, ink), ...)` at `:290` and `:299`, `readAsPoemByOcr(inkFile(file, fallback.ink), ...)` at `:746`, and `readAsPoemByOcr(inkFile(file, ink), text, stavesFound, sungLineFound)` in place of `:411-412`, deleting the `stem` line at `:411`; the import at `:65` gains `inkFile`. Net: `ScoreUploader.svelte` 1358 to 1357. This changes the OCR's input for a JPEG or PNG poem from the original to the same greyscale ink the PDF route already OCRs; report it as a change, not a fix. If the decoder also fails, the existing `ImageUndecodableError` is thrown, so the existing refusal still shows for a broken file.
2. **The decoder is loaded only for a HEIF picture**, by dynamic `import()`, never on page load, and never for a JPEG, PNG, or PDF. It runs in the page or a Worker, whichever loads in Chromium; say which.
3. **The decoder's files are served from Ilya's own origin** (N.197's direction: no outside service at run time). If the package resolves its `.wasm` by `new URL(..., import.meta.url)`, let Vite emit it under `_app/immutable/` and say so. Otherwise add `apps/web/scripts/copy-heif-wasm.mjs` on the pattern of `copy-pdfjs-wasm.mjs` (named required files, rebuilt each run, licence text copied beside the binaries, exits non-zero when a file is missing), wired into `dev` and `build` in `apps/web/package.json:9-10` after `copy-ort-wasm.mjs`, writing to `static/heif/`, which goes into `.gitignore` beside `static/pdfjs-wasm/`. Never under `/omr/`, which the service worker refuses to cache (`static/sw.js:60`), and never inlined as base64: the `.wasm` is its own file, which the LGPL's replacement condition and the lazy load both need. The service worker caches it after the first HEIC (`sw.js:74-85`); do not add it to `APP_SHELL` (`:23-28`). `vercel.json` is untouched. The report gives the byte count of every file the browser fetches for one HEIC and of every file the copy script writes (`CONTRACT.md` section 8). The ship waits for Dann to hear that number.
4. **The orientation flag** (EXIF or HEIF `irot`): the page must come out upright. Say what the chosen decoder does with rotation, and if it does not apply it, apply it.
