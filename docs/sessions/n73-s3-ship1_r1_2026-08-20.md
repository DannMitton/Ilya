## 2. Where the tree disagreed with the brief, and which won

**The tree won every time.**

### 2.1 The metadata block was inside the scroll, and the brief's build list did not say to move it

Brief §2.2 item 1 says NOTATION becomes the first child of the flex column
"beside the metadata block", which reads as though the metadata block were
already pinned. It was not. `MetadataFields` was the first child of
`.root-panel`, inside the one scrolling element, and it scrolled away with
everything else.

Brief §2.5 item 1 settles it: "the metadata block and NOTATION hold still at
the top." So the move is in scope even though §2.2 does not list it.

**What that cost.** `MetadataFields` and the Q4 provenance line left
`RootPanel.svelte` for the `pieceAnchor` snippet in `+page.svelte`. Five props
left with them: `metadata`, `onmetadatachange`, `fromScore`, `onrevert`,
`arrangerProvenance`. Nothing about the block changed except who renders it.
The `.shane-provenance` rule travelled with its markup for the third time, for
the reason it travelled at S2: Svelte scopes a rule to the component that
authors it.

**The dictionary error block stays first in the scroll**, which is no longer
first in the drawer. Its own comment says "persistent, stays at top" and it
still is, of the scroll. Recorded as a decision, not smuggled.

### 2.2 The mockup's Piece is ONE line. The tree's metadata block is six fields

`fable-gui-mockup_r1_2026-08-18.html:310-312` draws Piece as a single field,
`Aria or song title · Composer`. The tree's `MetadataFields` is a heading and
six fields with a reset. **The tree won**, because the brief says the tree wins
and because collapsing the metadata block into one line is a design decision
nobody has made. The consequence is measured in §4 and it is the largest
finding of this ship.

### 2.3 The takeover is a visibility switch, not a conditional mount

Brief §2.2 item 4 says `Calibrate` "replaces the drawer's whole interior with
the ritual". Building that as `{#if calibrating}` would have shipped a
regression, and this was found by reading the tree before writing:

**The page's mirror of the voice is published by an `$effect` inside the
wizard** (`CalibrationWizard.svelte:1092-1102`, the `onActiveProfileChange` effect).
`shaneFormants`, `shaneVoiceName` and `shaneCharacteristics` have no other
writer. Two things read them: `VoiceProfilePane`, which is the marked score's
whole page, and the Print guard for that document. **A wizard that only mounts
inside the takeover leaves the marked score with no voice, and Print on it
disabled, until the singer opens the takeover once.**

So all four regions render whenever Studio is the destination, and `.stowed`
gives three of them up to `display: none` while the fourth has the drawer. The
wizard mounts at boot exactly as it does today, on the same `isStudio` gate the
old NOTATION anchor used, so nothing about Learn and Guide changed either.

**Measured, and this is the positive control for the decision:** on a seeded
origin holding one calibrated voice named `Dann`, the anchor reads `Voice: Dann`
with `Re-calibrate` **at arrival, with the takeover never opened**, and Print on
the marked score is enabled with a voice and no score. Under a conditional mount
both would have been wrong.

### 2.4 The retract states needed no machinery; the scroll did

Brief §2.2 item 5 asks for scroll and retract restoration. Because nothing
unmounts, `notationExpanded` and `wizardCollapsed` survive on their own. The
scroll does not: `display: none` drops the box, and a box with no layout has no
`scrollTop`.

**A plain `$effect` was written first and it was wrong, and the browser said so.**
`$effect` runs AFTER the DOM update, so the capture read `scrollTop` on an
element that was already stowed and read 0; backing out of a drawer scrolled to
300 landed at 0. `$effect.pre` runs before the update, while the element still
has its layout. Measured before: 300 → 0. After: 300 → 300.

### 4.1 The ruling, built on Dann's instruction of 2026-08-20

(`fable-gui-session-record_2026-08-18.md:12-15`, ruling 2) and repeated in the

### Second repair: the marked score's page did not centre

**Reported by Dann walking ship one, with two screenshots of the deploy.**
**NOT A REGRESSION, and it predates every part of N.73 S3:** it is present on
`81438d4`, before S2.

**The cause, now measured rather than reasoned.** `PageFit`'s `.paper-fit` is
`width: 100%`, so `.main-content`'s `align-items: center` centres a box that
already fills the desk and has nothing left to give. What centres a sheet is the
page stack's own container. `Paper.svelte` wraps the transcription in
`.paper-container`, whose rule is a flex column with `align-items: center`.

**Where the tree disagreed with the report, and the tree won.** The report said
`VoiceProfilePane` renders its articles into `PageFit` with no equivalent
container. **It has one, and it already matches.** `.fit-paper-container`
(`VoiceProfilePane.svelte:987`) is byte-identical to `.paper-container`, and the
SCORE branch has been wrapped in it all along (`:711`). **Only the empty-state
envelope branch was bare**, which is the state Dann sees, because the other one
needs a score ingested. So the two could be made to match, and the repair is the
existing rule applied to the branch that never had it: one
`<div class="fit-paper-container">` at `VoiceProfilePane.svelte:819`. **No new
mechanism and no new rule.** No `role="region"` and no `aria-label` on the
wrapper: the article already carries its own label, and an unlabelled region is
not exposed as a landmark.

**Also corrected against the tree:** `STATE.md`'s 2026-08-20 entry says the
envelope article renders "outside `PageFit`". It renders INSIDE `PageFit`, in
its `content` snippet. It is outside a CONTAINER, which is a different thing and
is the actual fault.

**The four numbers, measured, at three desktop viewports.** Left edges in
pixels. **The defect needs a desk WIDER than the 816 px page**, which is why an
early reading at 1400 with the drawer open showed nothing: there the desk is the
page's width exactly and the two agree by accident. Dann's window is wider, so
he sees it with the drawer open.

| viewport | desk head | marked page BEFORE | marked page AFTER | gap closed |
|---|---|---|---|---|
| 1400 × 900, drawer closed | 292 | **32** | **292** | 260 |
| 1680 × 1050, drawer open | 692 | **552** | **692** | 140 |
| 1920 × 1080, drawer open | 812 | **552** | **812** | 260 |

**The positive control, run in the same browser at the same sizes:** the
transcription's page sits at 292, 692 and 812, on the desk head's left edge,
before and after. `.paper-fit` measured identically for both documents in every
case (left 32 width 1336, left 552 width 1096, left 552 width 1336), so the only
thing varying between the two documents was the container. The 260 px gap at
1920 is exactly `(1336 − 816) / 2`.

**An instrument error, caught and named.** The first BEFORE run reported the
marked page already centred at all three sizes. It had measured the FIXED build:
the shell's working directory had been reset, so the `cp` that saved the fixed
file and the edit that reverted it both failed on relative paths, and the run
proceeded against unchanged source. The numbers above come from a second run
with absolute paths, whose revert was confirmed by grep before the browser
started.
