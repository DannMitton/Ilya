1. **Detect, and where.** In `applyArrival` (`+page.svelte:3152`), before the `mergeOnUpload` call at `:3263`, for origin `'restore'` and `'upload'` alike: a stored map whose keys have the old reader's id shape, the shape `correction.ts:636-662` documents and `reader-ids.test.ts` guards (`r{measureIndex}-{x}` or `r{measureIndex}-{x}-{ordinal}`), while the parsed reading's sung events carry none of those names. `migrateCorrectionIds` (`correction.ts:665`) tests a four-segment count, not this shape, and runs at library load (`library/library.ts:85`) before any reading exists, so an r-keyed `corrections` map is re-keyed by this brief's new function in `applyArrival`, not there. 2. **Re-key, DESK DEFAULT method.** Within each bar, order the old seats by `x` and the current reading's syllable targets (`syllableTargetIds`, `pairings.ts:300-309`) by onset. Where the counts agree, pair in order. Where they disagree, and homr's reading carries a page position for every note (`<!-- imgpos: x, y -->`, parsed by `omr/join-pages.ts:435-437`), pair each old seat with the target whose `imgpos` x is nearest in bar-relative terms (both normalised to the bar's own span: old seats against the old bar's min and max x, targets against the bar's `imgpos` min and max), accepting a pairing only when it is one-to-one; otherwise leave the bar's seats under their old keys and count them. Record which `imgpos` scale the reading carries; it never has to match the old reader's scale, because only bar-relative positions are compared.

So the report gives the old map's highest bar index plus one against the reading's measure count, and a per-bar table saying which rule placed each bar or that it was left; a run of consecutive bars left from some bar onward is that shift, and is reported, not repaired here.
