## Step 0: the measure, before any change

Instrument: a Playwright script (session scratchpad, not committed) that visits online, then goes offline, and logs for `/data/*` each response (with `fromServiceWorker()`), each failed request, the `[Ilya]` console lines, the non-chunk keys in IndexedDB `ilya-data`, and whether Text draws a line (`[data-word-index="0-0"]` after typing a poem; the page draws none when the dictionary did not load, `+page.svelte` via `emptyTextNotice`/`entryCount`).

- **(a) no worker.** `pnpm dev` on `localhost:5173` (`app.html` registers no worker on `localhost` or `127.0.0.1`). The document cannot be made to fail while the dev server is reachable, so (a) is: online visit, then `context.route('**/data/**', abort('internetdisconnected'))` and a fresh page in the same context. This is a browser-level refusal of every `/data/` request, not a true offline; it is the closest the repository's set-up gives. A second (a) variant aborts only the supplement and the blurb.
- **(b) with a worker.** `pnpm build` (it ran in the lane; `fetch-omr-models.mjs` found the models), `apps/web/build` served by a small Node static server with an index fallback on `127.0.0.2:4173`. `127.0.0.2` is not in `app.html`'s dev-host list, so `sw.js` registered; after two visits `navigator.serviceWorker.controller` was true and the worker's cache held `/data/singer-supplement.json`, `/data/blurb-composer.json`, and `/data/homographs.json`. Then `context.setOffline(true)` and a new page. The offline document loaded from the worker's cache.

## What I changed

- `apps/web/src/lib/loader.ts` (754 lines before, 850 after; under 1000, no ratchet entry, none added):
  - `MANIFEST_STORE_KEY = 'ilya-dict-manifest'` replaces `CACHE_HASH_KEY` (`'ilya-dict-hash'`), which nothing wrote or read (DESK DEFAULT of the brief; removal stated here). Two more keys: `data-singer-supplement` and `data-blurb-composer`. They are deliberately not `supplement` and `blurb`: those are in `LEGACY_CACHE_KEYS`, which `cleanLegacyCache` deletes on every start.
  - `getStored` and `setStored` (single values in the same `cache` store), `isManifest` (a stored value is a manifest only if it has a string `hash` and `files` or `file`).
  - `setCacheChunked` now returns `Promise<boolean>`, true only if every write completed (it still swallows IndexedDB errors, as before). `loadDictionaryData` returns `{ lines, written }`, with `written` already resolved for a cache hit.
  - Step 1: when `fetchManifest()` fails (rejection or HTTP error), `loadDictionary` reads the stored manifest, logs `console.warn('[Ilya] Dictionary manifest unavailable; starting from the stored copy.')`, and goes on from the `cacheKey` line unchanged; with none stored (or an invalid one) the original error stands, word for word.
  - The manifest is stored by chaining onto `Promise.all(chunkWrites)` after the dictionary loop, only if every write returned true, and not awaited. Chosen: chained, not awaited, so the online start does not change its timing; the writes were already fire-and-forget. A manifest read from the store is not written back.
  - Step 2: `loadJsonFile(url, storeKey)`: a rejected `fetch` reads the stored copy (if none, rethrows the network error); a response that is not ok throws `HTTP <status>: ...` as before, whatever is stored; a good response is stored in the background.
  - Header comment updated for the two new behaviours.
- `apps/web/src/lib/loader.test.ts`: 10 new tests under "loadDictionary without a connection (N.195)", driving the exported `loadDictionary` with a mocked global `fetch` and `fake-indexeddb` on `globalThis` (a new `IDBFactory` per test; the loader never closes its connections, so deleting a database would block). `openDB` and the other internals are not exported.
- `apps/web/e2e/offline-dictionary.test.ts`: the (a) case as an end-to-end test (online visit, wait for the stored manifest, close the page, refuse `/data/**`, new page, Text transcribes).
- Not changed: `sw.js`, `+page.svelte`, the online path (manifest first, `cache: 'no-cache'`), the gloss and homograph tiers.
- Not "derived" in the sense of `CONTRACT.md` section 8: the stored manifest and the two JSON copies are the shipped files' own contents, as the dictionary chunks already are. Stating it so Dann can strike it.

## Step 0 reads the brief asked for

- `getCachedChunked` returns `null` on a missing meta (`if (!totalChunks) return null`) and on a missing chunk (`if (chunk === null) return null`), in `loader.ts` as at this tip. So a stored manifest that points at deleted or half-written keys falls to today's error.
- Order on a hash change online: `cleanLegacyCache(manifest.hash)` (fire-and-forget) deletes old `dict-` and `gloss-` keys, new chunks are written, then the new manifest. A crash in between leaves an old manifest and no old keys; the offline start then hits the original error. Pinned by test (d) for the replacement, and by reading for the crash.
- The IndexedDB readers of `ilya-data` are `loader.ts` alone (the library is `ilya-library`); the e2e test and my scripts read it for measurement only.

## Cross-site line and batch C

- `sw.js` unchanged; its manifest branch (network-first, then `caches.match`) still finds nothing offline, which is why the loader holds the copy.
- The gloss tier reads `manifest.glossFiles` from the stored object (it needs more than the hash): measured working offline in (a) and (b), loaded from IndexedDB with no request. Note the gloss chunks exist only if an earlier online start got that far (they load on idle); if not, the gloss tier's own failure is non-fatal, as before.
- `cleanLegacyCache(manifest.hash)` keeps by hash and now runs with the stored manifest's hash on an offline start: it keeps that hash's keys. The stored manifest's hash is the one the chunks were written under, because it is stored only after those writes returned true.
- Batch C's update check is in the tree now (`apps/web/src/lib/update-check.ts`, 84 lines). `refreshToNewVersion` probes `/_app/version.json?refresh=<stamp>` and returns `'offline'` without deleting anything if the probe fails; when it succeeds it deletes only `caches` entries whose key starts `ilya-` (`CACHE_PREFIX`) and reloads. It never touches IndexedDB. So: an offline start from the stored manifest, then a Refresh pressed offline, returns `'offline'`, deletes nothing, and the notice stays up; and a Refresh pressed online leaves the stored dictionary and manifest in IndexedDB.
