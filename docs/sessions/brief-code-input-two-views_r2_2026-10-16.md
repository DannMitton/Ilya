## 1. What the singer sees and gains

Today Input is one field. It is labelled "poem" (`apps/web/src/lib/i18n.ts:730`, `:245`), but what seats the notes is whatever is in it, so on 2026-10-14 Dann had to retype Tolstoy's poem as Tchaikovsky set it, repeats and the score's punctuation included, before 172 of 172 notes seated, and the Text tab then showed the retyped text, not the poem (`QUEUE-archive.md:188`). One field cannot hold two texts.

After this brief, above the field's top right corner sits the segmented pair the tab bar already uses, **Poem | Lyrics**. **Poem** is the poet's published text, the origin: lines and stanzas, the poet's punctuation and capitals, no hyphens, no repeats. **Lyrics** is the sung text: the composer's words, repeats, omissions, and alterations, in the edition's spelling. Syllable hyphens are not part of this slice: a score's words fill the field as whole words on one line (`apps/web/src/lib/score/vowel-resolver.ts:255`, `:344-346`), and a hyphen typed inside a word reaches the dictionary as a letter (`pipeline.ts:582`; `packages/phonology/src/engine.ts:701`), so the word reads as unknown, with no stress and no gloss (`pipeline.ts:670`, `:734`). Teaching the engine that a typed hyphen is a syllable break is its own row after this one (`pipeline.ts` is at 1064 of 1065); the alignment's hyphen rule in section 5 stays so that row changes nothing here. Ruling default 12's hyphen line stands as a desk default for that row. Under the control, one line always says which view this is. In Lyrics, every word that differs from the poem is coloured sage, repeats included; hyphens are never coloured. In Poem, words the song does not set are muted grey, never altered. A file dropped on the field goes where its content belongs whichever view shows, and the line says where it went. Text and Markup draw from Lyrics, as they draw from the one field today, so nothing the singer sees on the page changes except that the poem has a home.

The singer gains the poem back without losing the seating, and a two-tap comparison of what the composer did to the poem.

## 3. The data model: one field name stays, one is added

**Keep `SongRecord.poem` as the text that seats, which the singer now sees as Lyrics. Add one optional field for the Poem view.** Reason: every path that seats, transcribes, diffs, and exports reads `poem` and `inputText` today; keeping them as the Lyrics text changes nothing in seating, and an older Ilya importing a newer binder drops the new field and keeps the seats, as it does with `seatedText` and `tempo` (`types.ts:111-127`). The alternative (rename `poem` to mean the poet's text, add `lyrics`) inverts the field under every existing reader and loses the seating on an older import. Code names the new field and documents the inversion of the English words in the type's comment, in the house voice of that file. `origin` is taken twice: a pairing's `origin` is its slot (`pairings.ts:341`) and an arrival's `origin` is `'upload'` or a restore (`+page.svelte:2884`), so Code names the field something else. Two readers follow it: `proposeName` falls back to the first four words of `record.poem` (`songs.ts:51`), so the new field is preferred when non-empty (DESK DEFAULT); and `nameIfUnnamed` runs inside `handleInput` only (`+page.svelte:2462-2466`), so a poem pasted into Poem names an unnamed song too (DESK DEFAULT).

- The new field is optional and additive: absent means no poem has been given. Stored only while non-empty (`recordFromFields` pattern, `library.ts:104-129`); `validateRecord` accepts a string and marks anything else malformed, as `poem` is handled (`library.ts:172-173`).
- **Existing songs change nothing:** their text stays `poem`, which the singer sees as Lyrics; the Poem view starts empty (ruling default 3).
- `doc` gains the matching field and snapshot entry (`document.svelte.ts:263-278`); the save scheduler already covers the record.
- No schema bump. No derived value stored: the colouring and the line breaks (section 5) are computed on render.

## 5. Colouring, and the poem's line breaks

The comparison is a display-time word alignment, not stage 3's reconciliation. Build it as a pure module with tests (under `apps/web/src/lib/text/`, Code's name), taking two strings and returning, for each Lyrics word, whether it matches a poem word, and for each Poem word, whether it is set.

- **Tokens:** words, split on whitespace; hyphens inside a Lyrics word are joined before comparing and never count as a difference (Dann 00:40). Case folded, punctuation at a token's ends stripped, ё folded to е, both sides passed through `modernisePreReform` where it returns a form (`pipeline.ts:565` is how the pipeline uses it), so an old-spelling word and its modern form match.
- **Alignment:** longest common subsequence over the two token lists in order, so a composer's repeat shows as an extra, unmatched copy in Lyrics (coloured) and a composer's omission as an unmatched poem word (greyed). A reordered passage shows as both; that is the truth of it. A word altered by the composer is unmatched on both sides.
- **Colour:** the field's running text is `var(--ink-primary)` (`IntakePanel.svelte:782`; `app.css:28`), not sage, so sage reads. The token is `--sage-ink` (`#455238`, `app.css:189`), the sage family's label ink at OKLCH L 0.420, which the sheet says clears 7.02 on cream (`app.css:186-189`); `--sage` itself (`#839275`, `:42`) is the band colour at L 0.640 and is not an ink. Grey for a poem word the song does not set: `--ink-tertiary` (`app.css:30`, captions and placeholders). DESK DEFAULT on the two tokens; the hue is Dann's (00:32, 00:40). Because a textarea cannot colour its own text, render the active view as a styled layer behind the textarea with the textarea's text transparent and its caret inked, or as a contenteditable; measure both on a phone before choosing, and say which you built and why. The caret, selection, typing, paste, and drop stay a plain textarea's.
- **Line breaks:** when Lyrics is first filled from a score's words (one line, `scoreWordsText`, `vowel-resolver.ts:344-346`) and a Poem exists, break the Lyrics text at the points the alignment maps to the poem's line ends; an unmatched run (reordered or omitted) stays on its own line. Once the singer has edited Lyrics, her line breaks stand. When no Poem exists, Lyrics keeps whatever lines it has (the existing restore rule, if any, is left as it is). Four sites compare `doc.inputText` with the one-line `scoreText` by string equality: the `from score` tag (`+page.svelte:400`), the score's own seat (`:623`, `:2019`), and the waiting seat (`:1994`); the fill itself is `:2883-2887`. Any rewrite of the Lyrics text at fill time, line breaks included, turns all four off and the score's own seating path (N.134, N.144) with them. The common order is score first, poem later (`QUEUE-archive.md:188`): when a Poem arrives while Lyrics still holds the score's words unedited, the same rule applies; once the singer has edited Lyrics, her breaks stand. Report how many seats moved on the fixture when the breaks were applied; the expectation is zero.
