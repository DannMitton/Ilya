## Why it happens, and the model to follow

- The chips set the glyph as text: `<span class="mus">{beatGlyph(c.unit, c.dots)}</span>` (`apps/web/src/lib/tempo/TempoControl.svelte:90-91`), `font-family: 'Finale Maestro'; font-size: 1.5rem` (`:191-194`), in a button with `line-height: 1` (`:153-166`). A SMuFL metronome note's ink is not centred in its font box: the notehead sits at the baseline and the stem rises from it (`apps/web/src/lib/score/CorrectionSurface.svelte:250-259` measured `noteQuarterUp` from 88.9 above the baseline to 13.2 below at 100 px). So the note sits where its metrics put it, not in the middle of the chip.
- **The model, "the other similar buttons":** Corrections' duration cells draw the same glyphs (`LENGTH_CELLS`, `apps/web/src/lib/score/correction.ts`; `beat-glyph.ts` takes its glyphs from the same table) by their **measured ink**: each glyph is measured once with canvas `measureText`'s `actualBoundingBox*` (`CorrectionSurface.svelte:303-323`, `measureGlyphs`), the set shares one common ink box (`commonInkBox`, `apps/web/src/lib/score/loupe.ts:240`), and each glyph is drawn in an SVG through a viewBox centred on its own ink (`centredViewBox`, `loupe.ts:253`; the `drawn` function at `CorrectionSurface.svelte:334-347`; the `cell` snippet at `:367-384`) at a fixed height (`NOTE_H = 26`, `:261`), inside a flex cell that centres it on both axes (`.cell`, `:1057-1071`). One box for the set gives one scale and the same margin in every cell; the comment block at `:230-259` explains why canvas and not `getBBox`.
