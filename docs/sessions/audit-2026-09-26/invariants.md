## Notes on scope and confidence

- Several rules above (6, 7, 8, 13) are the strongest candidates for phase 1's mechanical-gate work, because each has a concrete, cheap test shape and at least one (13) is demonstrably already broken.
- This table draws only from `CONTRACT.md`, `PRODUCT.md`, and `AGENTS.md` per task 3's instructions. `docs/memory/OPEN.md`, `STATE.md`, and `OWED.md` almost certainly contain more item-specific architectural rulings (the "NOTES NEVER MOVE" amendment history alone spans several of them); they were out of this task's named scope and were not read this session.
- Rule 1's determinism claim is the project's single most load-bearing architectural promise ("Ilya is not AI") and this session found no dedicated determinism test for it. This is worth flagging to Dann as a gap, not asserting as a defect, since the engine may already be trivially deterministic by construction (pure functions, no `Math.random()`/`Date.now()` in the hot path) without a named test proving it; that would need a grep for non-deterministic primitives in `packages/phonology/src`, not done this session.
