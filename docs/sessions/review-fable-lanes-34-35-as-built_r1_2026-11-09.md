### Faults and departures

**Finding 1 (before merge). A fill or a repair that spans a melisma note seats only its first syllable, and the receipt counts all of them.**
The join sends its text through `handleInput(text, 'paste')` (`poem-join.svelte.ts:148`; `+page.svelte:2335` `setLyrics: (t) => handleInput(t, 'paste')`), so the seats follow by `reseatByDiff` (`+page.svelte:2040`). That function's rule 3 puts each new slot at `anchor + 1` (`score/reseat.ts:277`) and, where that note already carries any pairing, counts the slot `unseated` and does not advance (`:310-312`). A `melisma` pairing is such a note (`:171-174` carries it through untouched). The join's `buildRuns` skips melisma notes when it counts a run (`poem-join-wire.ts:162`), so a run of two open notes with a melisma between them has `needs [2]`, the count rule passes, and the fill is applied. I probed `reseatByDiff` with notes n0 «раз», n1 open, n2 melisma, n3 open, n4 «два» and a diff inserting «три четыре»: result `seated 1, unseated 1`, n1 «три», n3 undefined. So the singer sees one syllable under n1, a blank non-continuation note at n3 (a `no-syllable` mistake under `CONTRACT.md` §0.1, "and none"), the second word unseated in Lyrics, and a receipt saying "2 syllables filled from your poem" (`poem-join.svelte.ts:137` counts `p.slots`). A repair of a word whose old seats straddle a melisma note fails the same way (the vacated notes are refilled from the anchor one by one). The same path serves "Fill from the poem" (`poem-join.svelte.ts:204-230`), where amendment 9 accepts words past the last open note staying unseated, but not a blank open note after a melisma. No test covers it: `poem-join.svelte.test.ts:29-32` stubs `setLyrics` as a plain assignment to `inputText`, so the reseat never runs under test.
Amendment 1: in `PoemJoin.run` and `fillBar`, after `deps.setLyrics(...)`, read `deps.state()?.pairings` again and count the `syllable` pairings whose `origin` word is one of the written tokens; where the count is under the slots written, call `revert()` and say so on the console line (Dann 10:36, a cross-check that looks again). Whether the reseat has run by the time `setLyrics` returns is NOT ESTABLISHED by me (`joinText('paste')` → `transcribeVerdict` → `transcribeText`, `+page.svelte:2498-2508`, `:2329-2333`; I did not read `transcribeVerdict`); if it has not, the check runs on the next pause. Alternative, smaller but stricter: `buildRuns` offers `count-refused` for any run whose notes are not adjacent in the vocal line, and `planJoin` is told which Lyrics words have non-adjacent seats and keeps them as offers. Either way the test in `poem-join.svelte.test.ts` needs a `setLyrics` that runs `reseatByDiff`.
