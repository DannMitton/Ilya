## STEP −1. Ground truth, and the collision

**Method.** Per-row ink coverage inside a 200 px vertical slice, 13 slices
across x = 0…2583, the desk instrument of `ENVIRONMENT.md:945-951`, the one
that recovered s = 17.0 and found the original bug. Peaks are matched across
slices as whole **five-line combs**, never as individual lines, so a tracker
cannot slide onto a neighbouring line. Coverage is deliberately *not* the
substrate's bridged extent, so the truth set is not established with the
instrument §5.4 tests.

**What could make it lie.** It assumes five lines per staff, so a real six-line
artifact would be missed; it needs ≥ 0.45 coverage in a 200 px window, so a line
faded below that across a whole slice is invisible; and comb matching can in
principle lock onto a regular non-staff grid. Against that: it reproduces the
working reader exactly on the control.

notehead merges with the line imports glyph rows into the truth set. Stated

**S7. §5.6 is reported twice**, over the full truth set as asked and over the 60
rows a decider would accept. The second is the sentinel's actual binding point;
the first overstates the breach.

**S8. Step −1 used a fixed peak threshold: 0.45 coverage, prominence 0.12,
radius 7, 200 px slices, 13 slices across x = 0…2583.** Not derived per page. It
is a diagnostic instrument, not runtime code, and it is validated against the
